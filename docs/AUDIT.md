## 1. الملخص التنفيذي (Executive Summary)
أظهر الفحص الشامل لمستودع CodeQ وجود فجوة جوهرية بين ما تم الترويج له في ملف `README.md` والوظائف البرمجية الفعلية في الكود؛ حيث تبيّن أن النظام القديم عبارة عن واجهة ثابتة أولية مع خادم تجريبي يحتوي على ردود ذكاء اصطناعي وهمية ومصادقة صورية، بالإضافة إلى ثغرة أمنية حرجة بتسريب مفتاح API داخل ملف `.env`. علاوة على ذلك، لا يمكن تشغيل بنية الخادم الحالية (Node.js + MongoDB) على استضافة GitHub Pages الثابتة دون تحويل المعمارية بالكامل.

## 2. التدقيق المعماري والبنية البرمجية

| العنصر | الحالة السابقة | التحليل والتقييم |
| :--- | :--- | :--- |
| **محرك الذكاء الاصطناعي** | ردود وهمية (Mock Data) | تم تضمين 3 إجابات ثابتة فقط داخل مصفوفة (`demoAnswers`)، وأي سؤال آخر يرجع نصاً عاماً: *"الكود سيكون هنا في الإصدار الكامل"*. لا يوجد أي اتصال فعلي بنموذج ذكاء اصطناعي حقيقي. |
| **الواجهة الأمامية (Frontend)** | HTML/CSS/JS تقليدي غير مجمّع | لا توجد أدوات بناء حديثة (No Bundler)، لا يوجد تقسيم للكود (Code Splitting)، الاعتماد على مكتبات CDN قديمة، وغياب مسارات الأصول المتوافقة مع النشر الفرعي (`/codeq/`). |
| **الخادم (Backend)** | Express + In-Memory Arrays | الخادم يحفظ الأسئلة والمستخدمين في مصفوفات عشوائية في ذاكرة RAM تفقد بياناتها مع كل إعادة تشغيل. غير متوافق بنيوياً مع استضافة GitHub Pages الثابتة. |
| **نظام المصادقة والحسابات** | مصادقة وهمية وغير آمنة | مقارنة كلمات المرور بنص مجرد (`user.password === password`)، وتوليد كائنات مستخدم وهمية وحفظها في `localStorage` دون تشفير أو رموز JWT فعلية. |
| **محول الماركداون (Markdown)** | تعبيرات نمطية بدائية (Regex) | استخدام دوال استبدال نصية بسيطة تنهار عند التعامل مع الجداول، القوائم المتداخلة، أو كتل الأكواد المتعددة ذات اللغات المختلفة. |
| **النشر و CI/CD** | غائب تماماً | لا يوجد ملف `.gitignore`، لا توجد إعدادات GitHub Actions، لا يوجد ملف `.nojekyll`، ولا توجد معالجة لصفحة `404.html` لتوجيه المسارات. |

## 3. الأخطاء الأمنية والحرجة المكتشفة (Security & Critical Findings)

1. **تسريب مفتاح Google Gemini API في الكود (`server/.env`):**
   - وُجد مفتاح مسجل نصياً: `GEMINI_API_KEY=AIzaSyB8FM39mqIyvxeaQ0TZ7KTgJhQ0887ItuY`.
   - **الخطر:** انتهاك أمني يتيح استغلال الحساب من أي طرف، ومخالفة لقواعد حماية البيانات والسياسات البرمجية.
   - **الإجراء الفوري:** استبعاد ملفات `.env` من التتبع، إضافة `.gitignore` شامل، وحذف المفاتيح من الكود كلياً.

2. **تخزين كلمات المرور كنص صريح (Plaintext Passwords):**
   - دالة `handleRegister` و `handleLogin` تتعامل مع كلمات المرور دون أي تجزئة مشفرة (Bcrypt) وتثق بالمدخلات مباشرة.

3. **روابط ثابتة إلى بيئة التطوير المحلية (Localhost Hardcoding):**
   - وجود `http://localhost:3000/api` بشكل ثابت في `client/script.js` مما يجعل الموقع معطلاً تماماً بمجرد رفعه على GitHub Pages.

## 4. خطة إعادة البناء المعمارية المقترحة (Target Architecture)

لتحقيق متطلبات المستخدم الصارمة: **(نشر حقيقي على GitHub Pages + عدم طلب أي API Key + ذكاء اصطناعي حقيقي وفعلي + واجهة عربية متكاملة)**:

1. **معمارية الواجهة الحديثة (Modern Client Architecture):**
   - اعتماد **Vite** كمحرك بناء فائق السرعة، مع مسار أساسي نسبي متوافق مع GitHub Pages (`/codeq/`).
   - بنية حزم قائمة على المكونات (Component-driven) والتصميم العربي الحديث (RTL-First) بخطوط عربية ممتازة (IBM Plex Sans Arabic / Cairo).
   - استعراض الأكواد مع محرك Markdown كامل وموثوق يدعم تلوين الصياغة (Syntax Highlighting) لجميع لغات البرمجة وزر نسخ مستقل لكل كتلة كود.

2. **معمارية الذكاء الاصطناعي بدون مفاتيح (Zero-Key AI Engine Architecture):**
   - **المستوى الأول (In-Browser WebGPU/WebLLM):** تشغيل نماذج لغوية حقيقية بالكامل داخل متصفح المستخدم عبر WebGPU بدون أي خادم أو وسيط (مثل `SmolLM2-360M-Instruct`, `Qwen2.5-Coder-1.5B-Instruct`, `Llama-3.2-1B-Instruct`)، مع مؤشر تقدم تنزيل حقيقي، فحص توافق العتاد وذاكرة المتصفح، وعمل النموذج دون اتصال بالإنترنت بعد التحميل الأول.
   - **المستوى الثاني (Free Zero-Key Cloud Provider - Puter.js):** استخدام طبقة Puter.js الرسمية المدمجة التي تتيح استدعاء نماذج متقدمة مجاناً للمستخدمين بدون الحاجة لتسجيل أو إدخال أي مفتاح من قِبل المطور أو المستخدم، مما يضمن عمل المنصة على الأجهزة القديمة أو الهواتف التي لا تدعم WebGPU.
   - **المستوى الثالث (طبقة المزود الموحد Unified Provider Interface):** واجهة قياسية تسمح بالتبديل السلس بين المعالجة المحلية السحابية، والتدفق الحي للإجابات (Streaming Responses)، وتوفير خيار اختياري مستقبلي للمستخدم لإدخال مفتاحه الخاص (BYOK) في متصفحه إن رغب، دون إجباره على ذلك إطلاقاً.

3. **إدارة البيانات والحسابات المتوافقة مع GitHub Pages:**
   - استبدال المصادقة الصورية بحفظ محلي كامل ومستمر (Local-First Architecture) باستخدام `IndexedDB` و `LocalStorage`.
   - إدارة جلسات محادثة كاملة (Sessions/Threads)، سجل أسئلة، بحث لحظي داخل المحادثات، حفظ في المفضلة، واستيراد وتصدير المحادثات (JSON / Markdown).

4. **الأتمتة والنشر (Automated CI/CD):**
   - إنشاء GitHub Actions Workflow رسمي يبني المشروع ويتحقق من سلامة الاختبارات وينشر تلقائياً إلى GitHub Pages.
   - إضافة ملف `.nojekyll` وملف `404.html` لإعادة توجيه مسارات SPA بسلاسة.
